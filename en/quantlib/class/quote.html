# QuantLib-Python: Quote Class

QuantLib Guide | 2025.01.24

Quote Class

  • The Quote class and its subclasses like SimpleQuote class serve to objectify market underlying assets as Observables according to the observer pattern.
  • In QuantLib, the pricing engine for derivative valuation is managed collectively as a PricingEngine class, and each underlying asset is built up starting from the Quote class.

# Derivatives and Pricing

# Derivatives

The fundamental purpose of financial engineering is pricing derivatives. The term derivatives literally means products whose value is derived from changes in the price of underlying assets.

Therefore, the relationship between underlying assets and derivatives can be compared to inputs and outputs in a function. Just as output values change when input variables change, the theoretical value of derivatives automatically changes as the price of underlying assets changes.

Input: Underlying Asset -> Function: Pricing Mechanism -> Output: Derivative Value

# Pricing

Pricing refers to the process of measuring, in a rational way, what the theoretical value of a derivative would be under current market conditions.

In other words, pricing means recognizing changes in underlying assets that affect derivatives and calculating derivative values accordingly.

Ultimately, the key to pricing derivatives is immediately recognizing market changes and reflecting them in real-time in the pricing process.

# QuantLib Design Structure Feature: Observer Pattern

# Observer Pattern

Observer Pattern

  • When designing QuantLib, to faithfully incorporate the essence of pricing into its framework, the observer pattern, one of the design patterns commonly used in software engineering, was adopted as a major framework of QuantLib's design structure.

  • The Observer Pattern refers to a software engineering implementation style for automatically detecting changes and reflecting them when external changes occur. Technically, it's a design pattern where observers monitoring object state changes are registered to the object, and the object directly notifies each observer in the list through methods whenever state changes occur.

  • This observer pattern can be easily found in various software. A prime example is in Excel, where when you change the data that a graph is looking at, the graph automatically updates to match the data.

  • In other words, the observer pattern is responsible for constantly monitoring the observed subject and appropriately changing all related elements in real-time when changes occur.

  • The observer pattern is highly optimized for pricing mechanisms. This is because, as mentioned earlier, the essence of pricing is detecting changes in underlying assets and appropriately reflecting them in derivative prices in real-time. QuantLib's designers properly understood this common ground between software engineering and financial engineering to build QuantLib's framework.


# Observer and Observable

Observer and Observable

  • QuantLib's observer pattern basically consists of two components: the Observer that observes changes and the Observable that is being observed.

  • In QuantLib, Observer and Observable correspond to the pricing engine and underlying asset respectively. Since it's ultimately the underlying asset that affects derivative prices, changes in the underlying asset must act as a trigger to notify the pricing engine of new updates for derivative valuation.

  • The pricing engine as an observer closely watches the underlying asset as the observable, and when changes occur, it must immediately reflect this by repricing the derivative.

  • In QuantLib, the pricing engine itself for derivative valuation is managed collectively as a PricingEngine class, and each underlying asset is built up starting from the Quote class.

  • It's no exaggeration to say that QuantLib could become the optimal tool for financial engineering pricing thanks to the power of the observer pattern inherent in its structure.


# Observer Pattern Example
import QuantLib as ql

flag = None
def raiseFlag():
    global flag
    flag = 1

me = ql.SimpleQuote(0.0)
obs = ql.Observer(raiseFlag)
obs.registerWith(me)
me.setValue(3.14)
if not flag:
    print("Case 1: Observer was not notified of market element change")
flag = None
obs.unregisterWith(me)
me.setValue(3.13)
if not flag:
    print("Case 2: Observer was not notified of market element change")

# Quote Class Overview

Derivatives necessarily require underlying assets that form their basis. These underlying assets include things like stock prices, interest rates, exchange rates, and volatility. In QuantLib, before implementing underlying assets, specific real number values are always received to create underlying asset objects, and this is where QuantLib's Quote class is needed.

The Quote class has various subclasses, but the most commonly used class is the SimpleQuote class. This SimpleQuote class takes a specific real number as an argument and serves to turn it into an object.

Simply put, the SimpleQuote class can be thought of as a small container holding a numeric value. For numbers to serve as underlying assets, they must be contained in this SimpleQuote class container.

# Quote Class Structure

# SimpleQuote Class

The structure of the SimpleQuote class is literally very simple. This is because you just need to input the desired specific number into ql.SimpleQuote() as shown in the source code below.

import QuantLib as ql

# Construction
# ql.SimpleQuote(value)
underlying_asset = ql.SimpleQuote(250.0)

# DerivedQuote Class

Simple operations can be applied to input values through the DerivedQuote class.

import QuantLib as ql

s = ql.SimpleQuote(0.06)
# ql.DerivedQuote(quoteHandle, function)
d = ql.DerivedQuote(ql.QuoteHandle(s), lambda x: 10*x)

d.value()  # 0.6

# Quote Class Functions

The SimpleQuote class functions are also very simple.

  • value() method: Function to output the current contained value
  • setValue() method: Function to change the value contained in the object to a new input value
  • isValid() method: Returns True if the Quote class has a value
import QuantLib as ql

# Functions
print(underlying_asset.value())  # 250.0

underlying_asset.setValue(260.2)
print(underlying_asset.value())  # 260.2

print(underlying_asset.isValid()) # True

setValue() method

  • The setValue() method, which simply changes values, has a very close relationship with the observer pattern. As mentioned earlier, the observer pattern is a software engineering tool that notifies observers immediately when changes occur in the observable.

  • For the observer pattern to work properly, a trigger to notify observers of such changes simultaneously with the changes is needed. This setValue() method acts as that trigger.

  • Using this, derivatives can immediately recognize changes in underlying assets without explicit notification.

  • Thus, QuantLib achieves pricing efficiency through this observer pattern without requiring us to explicitly notify when changes occur. You'll be able to understand its utility through the introduction of subsequent classes.
