# QuantLib-Python: Schedule Class

QuantLib Guide | 2025.01.22

Schedule Class

  • The Schedule class is used to generate and manage important dates such as settlement dates and interest payment dates for financial products. This class simplifies schedule management for products with periodic cash flows, such as bonds or swaps.

  • The Schedule class generates schedule lists based on various dates and period information, helping to easily manage dates that are fundamental to important calculations in financial contracts.

# Schedule Class Overview

# 📆 Interest Payment Schedule

Most FICC (Fixed Income, Currency, Commodity) products that use interest rates as underlying assets, such as bonds, swaps, caps, and floors, have interest payment schedules. This interest payment schedule refers to a specific series of dates on which interest occurs periodically. Since interest typically occurs on 3-month or 6-month intervals in normal cases, theoretically thinking about such interest payment schedules is not particularly difficult.

However, in actual financial markets, specific interest accrual dates can vary slightly depending on each country's holidays, product-specific market conventions, and agreements with counterparties. In other words, what wasn't an issue in theoretical modeling can become a significant issue in actual financial markets. QuantLib's Schedule class is a very useful tool that can precisely implement these real-world details.

# 🔄 Schedule Class Use Cases

The Schedule class helps manage dates that are fundamental to important calculations in financial contracts by generating schedule lists based on various dates and period information.

The Schedule class can be used in various financial products. For example, it's used to generate interest payment schedules for fixed-rate bonds or cash flow schedules for swap contracts. This allows for automation of schedule calculations for complex financial products, reducing errors and standardizing schedule calculations.

# Schedule Class Structure

The Schedule class is inherently more complex in structure than the classes we've seen before. This is because the Schedule class is responsible for aggregating the classes and enumerations needed to generate interest payment schedules.

In other words, the Schedule class handles the functionality of reflecting various market conventions written in the term sheet to generate specific interest payment schedules.

ql.Schedule(Date effectiveDate,                              # Effective Date
            Date terminationData,                            # Maturity Date
            Period tenor,                                    # Interest Payment Period
            Calendar calendar,                               # Calendar
            BusinessDayConvention convention,                # Interest Payment Date, Business Day Convention
            BusinessDayConvention terminationDateConvention, # Maturity Date, Business Day Convention
            DateGeneration rule,                             # DateGeneration
            Bool endOfMonth)                                 # End of Month

# Key Parameters

The key parameters you need to understand for the Schedule class are as follows:

Parameters

  • Effective Date: The start date when the financial product takes effect. The schedule is generated from this date.
  • Termination Date: The end date of the schedule. Cash flows can occur until this date.
  • Tenor: Represents the frequency of the schedule, with options like monthly, quarterly, semi-annual, annual, etc.
  • Calendar: The business day calendar to apply to the schedule. It can adjust schedules reflecting specific region's holidays or weekends.
  • Business Day Convention: Rules determining how to handle dates that fall on weekends or holidays.
  • End of Month: A Boolean value determining the end-of-month criterion.

These parameters can be combined to easily define complex schedule structures for financial contracts.


# DateGeneration

Here, DateGeneration is an enumeration that determines how to create schedules for interest payment dates.

DateGeneration

  • 'ql.Backward`: Generates interest payment schedule backward from maturity date to effective date
  • ql.Forward: Generates interest payment schedule forward from effective date to maturity date
  • ql.Zero: No payment dates exist between effective date and maturity date
  • ql.ThirdWednesday: Sets all intermediate interest payment dates (excluding effective and maturity dates) to the third Wednesday of the respective month
  • ql.Twentieth: Sets all interest payment dates (excluding effective date) to the 20th of the respective month
  • ql.TwentiethIMM: Sets all interest payment dates (excluding effective date) to the 20th of March, June, September, and December

# endOfMonth

endOfMonth is a parameter that determines the end-of-month criterion. If this value is True and the effective date is the last business day of the month, it adjusts each interest payment date to align with the last business day of the month when generating the schedule.

endOfMonth

  • If this value is False, the schedule is generated using standard day count methods regardless of what day the effective date falls on.
  • For example, if February 28 is the last business day and endOfMonth is True, the interest payment date three months later would be April 30 (if it's a business day) rather than April 28.
import QuantLib as ql

# Components
effectiveDate = ql.Date(10, 6, 2023)
terminationDate = ql.Date(10, 6, 2026)
tenor = ql.Period(6, ql.Months)
calendar = ql.NullCalendar()
convention = ql.ModifiedFollowing
terminationDateConvention = ql.ModifiedFollowing
rule = ql.DateGeneration.Backward
endOfMonth = False

# Construction
schedule = ql.Schedule(effectiveDate,
                        terminationDate,
                        tenor,
                        calendar,
                        convention,
                        terminationDateConvention,
                        rule,
                        endOfMonth)

# Schedule Class Functions

The purpose of the Schedule class is to generate interest payment schedules based on market conventions and pass them to the financial product objects that use them.

For example, when implementing a Korean government bond using QuantLib, an interest payment schedule is needed in the process of creating the Korean government bond object, and this is performed by the Schedule class.

Due to these characteristics of the Schedule class, there aren't many explicit methods to use in actual implementation. This is because the Schedule class completes its role by passing its results to the product we want to price.

# Schedule Class Functions

However, let's look at the nextDate and previousDate methods that are often used in actual implementation.

Schedule Class Functions

  • nextDate(Date): Returns the next interest payment date after the input date
  • previousDate(Date): Returns the previous interest payment date before the input date
import QuantLib as ql

ref_date = ql.Date(15, 8, 2024)

# Functions
print(f'Previous Payment Date from {ref_date.ISO()} : {schedule.previousDate(ref_date).ISO()}')
print(f'Next Payment Date from {ref_date.ISO()} : {schedule.nextDate(ref_date).ISO()}')

## Output
## Previous Payment Date from 2024-08-15 : 2024-06-10
## Next Payment Date from 2024-08-15 : 2024-12-10

# MakeSchedule

Schedule 생성

  • ql.MakeSchedule(effectiveDate, terminationDate, frequency)

Optional params

  • calendar=None
  • convention=None
  • terminalDateConvention=None
  • rule=None
  • forwards=False
  • backwards=False
  • endOfMonth=None
  • firstDate=None
  • nextToLastDate=None
import QuantLib as ql

effectiveDate = ql.Date(15, 6, 2020)
terminationDate = ql.Date(15, 6, 2022)
frequency = ql.Period('6M')
schedule = ql.MakeSchedule(effectiveDate, terminationDate, frequency)
