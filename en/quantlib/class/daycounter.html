# QuantLib-Python: DayCounter Class

QuantLib Guide | 2025.01.20

DayCounter Class

  • The QuantLib DayCounter class implements various methods used for date calculations in financial markets. This class is used to calculate the number of days between two dates or calculate ratios between specific dates.

  • Since interest calculation methods are important in financial contracts, the DayCounter class provides various day count conventions (e.g., Actual/Actual, Actual/360, 30/360, etc.). This enables accurate interest calculations and maintains consistency between different financial products.

# DayCounter Class Overview

In financial transactions, there are rules commonly agreed upon by all market participants, and the FICC (Fixed Income, Currency, Commodity) markets have many diverse market conventions.

When pricing FICC products, the most important aspect is how to properly implement these various market conventions in detail.

Like holidays, day count conventions vary by country and market. QuantLib provides various day count methods through the DayCounter class.

Day Count Conventions

  • Day count conventions are mutual agreements on how to calculate interest for periods less than one year. This is a crucial detail in swap markets and bond markets where interest is exchanged on 3-month or 6-month intervals.
  • Since interest rates are quoted as annual rates, to calculate interest for periods less than a year, the time frame needs to be aligned on an annual basis.
  • Simply put, day count conventions involve determining two things: how many days to count in a year and how many days to count in a month.

For counting days in a year, there are ACT, 365, 360, and 252 conventions.

  • Here, ACT stands for Actual, which calculates the actual number of days in that year. If using ACT, a leap year would have 366 days.
  • The other conventions fix the year at 365 days, 360 days, or 252 days.

For counting days in a month, there are ACT, 30, and business days conventions.

  • ACT calculates the actual number of days in the interest period, while 30 considers each month as 30 days.
  • Finally, business days only counts business days, excluding holidays.
  • For example, using the 30 method for the period from August 2 to October 2 would result in 61 days (30 × 2 + 1) as it's two months plus one day.

When combining these two elements, we get conventions like ACT/365, ACT/360, ACT/ACT, 30/360, which are the market conventions for calculating interest days.

  • The numerator represents the monthly convention, while the denominator represents the yearly convention.
  • Each country uses different conventions: the US uses ACT/360, Europe uses 30/360, and Korea uses ACT/365.

# DayCounter Class Structure

Implementing the DayCounter class is very simple. Like the Calendar class, you just need to declare the method you want to use. Below is the code showing examples of each day count method.

import QuantLib as ql

# Construction
act360 = ql.Actual360()                          # ACT/360
act365 = ql.Actual365Fixed()                     # ACT/365
actact = ql.ActualActual(ql.ActualActual.ISDA)   # ACT/ACT (ISDA)
thirty360 = ql.Thirty360(ql.Thirty360.European)  # 30/360 (EU)
b252 = ql.Business252()                          # BusinessDay/252
simpledc = ql.SimpleDayCounter()                   # NASD

# DayCounter Class Functions

The DayCounter class has two main functions. One is the dayCount() method that calculates the number of days between two dates, and the other is the yearFraction() method that calculates the period between two dates in annual terms based on market conventions.

# 📆 dayCount()

The dayCount() method provides functionality to calculate the period between two dates on a daily basis according to the given day count convention.

import QuantLib as ql

# Construction
act360 = ql.Actual360()                          # ACT/360
act365 = ql.Actual365Fixed()                     # ACT/365
actact = ql.ActualActual(ql.ActualActual.ISDA)   # ACT/ACT (ISDA)
thirty360 = ql.Thirty360(ql.Thirty360.European)  # 30/360 (EU)
b252 = ql.Business252()                          # BusinessDay/252
simpledc = ql.SimpleDayCounter()                   # NASD

# Function
startDate = ql.Date(15, 5, 2024)
endDate = ql.Date(15, 8, 2024)

# dayCount(Date1, Date2)
print(f'Day Count by Actual/360 = {act360.dayCount(startDate, endDate)}')
print(f'Day Count by Actual/365 = {act365.dayCount(startDate, endDate)}')
print(f'Day Count by Actual/Actual = {actact.dayCount(startDate, endDate)}')
print(f'Day Count by 30/360 = {thirty360.dayCount(startDate, endDate)}')
print(f'Day Count by BusinessDay/252 = {b252.dayCount(startDate, endDate)}')
print(f'Day Count by SimpleDayCount = {simpledc.dayCount(startDate, endDate)}')

## Output
## Day Count by Actual/360 = 92
## Day Count by Actual/365 = 92
## Day Count by Actual/Actual = 92
## Day Count by 30/360 = 90
## Day Count by BusinessDay/252 = 65
## Day Count by SimpleDayCount = 90

# ⏰ yearFraction()

The yearFraction() method provides functionality to convert the period between two given dates into annual terms using a specific day count convention.

Each method outputs different results depending on how many days are counted in a year. In other words, the calculated interest amount differs depending on which market convention method is used.

import QuantLib as ql

# Construction
act360 = ql.Actual360()                          # ACT/360
act365 = ql.Actual365Fixed()                     # ACT/365
actact = ql.ActualActual(ql.ActualActual.ISDA)   # ACT/ACT (ISDA)
thirty360 = ql.Thirty360(ql.Thirty360.European)  # 30/360 (EU)
b252 = ql.Business252()                          # BusinessDay/252
simpledc = ql.SimpleDayCounter()                   # NASD

# Function
startDate = ql.Date(15, 5, 2024)
endDate = ql.Date(15, 8, 2024)

# yearFraction(Date1, Date2)
print(f'Year Fraction by Actual/360 = {
        round(act360.yearFraction(startDate, endDate), 4)}')
print(f'Year Fraction by Actual/365 = {
        round(act365.yearFraction(startDate, endDate), 4)}')
print(f'Year Fraction by Actual/Actual = {
        round(actact.yearFraction(startDate, endDate), 4)}')
print(f'Year Fraction by 30/360 = {
        round(thirty360.yearFraction(startDate, endDate), 4)}')
print(f'Year Fraction by BusinessDay/252 = {
        round(b252.yearFraction(startDate, endDate), 4)}')
print(f'Year Fraction by SimpleDayCount = {
        round(simpledc.yearFraction(startDate, endDate), 4)}')

## Output
## Year Fraction by Actual/360 = 0.2556
## Year Fraction by Actual/365 = 0.2521
## Year Fraction by Actual/Actual = 0.2514
## Year Fraction by 30/360 = 0.25
## Year Fraction by BusinessDay/252 = 0.2579
## Year Fraction by SimpleDayCount = 0.25
